## Priority 1 — Meta Tags (Highest Impact, Lowest Effort)

Add to **every** page via `generator/gpkit/build.py` (module pages) and `index.html` (hub). The generator change makes this permanent — hand-edits to built HTML are lost on rebuild per `docs/RULES.md`.

```html
<meta name="description" content="217 free AI/ML interview cards with Simple and Technical modes. Real systems, real numbers, the follow-up questions interviewers actually ask. No signup, no tracking.">
<link rel="canonical" href="https://gradientpath.site/05-statistics.html">

<!-- Open Graph -->
<meta property="og:type" content="website">
<meta property="og:site_name" content="Gradient Path">
<meta property="og:title" content="Statistics & Probability, Decision by Decision">
<meta property="og:description" content="40 interview cards on inference, experimentation, causality — each with drills, traps, and real production failures.">
<meta property="og:url" content="https://gradient.site/05-statistics.html">
<meta property="og:image" content="https://gradientpath.site/og/05-statistics.png">

<!-- Twitter -->
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="Statistics & Probability, Decision by Decision">
<meta name="twitter:description" content="Free AI/ML interview cards. Simple mode has zero notation; Technical mode is interview-grade.">
<meta name="twitter:image" content="https://gradientpath.site/og/05-statistics.png">
```

**Implementation notes:**
- Per-page `title` and `description` should be generated from module CFG data (`generator/mod05.py` etc.), not hard-coded.
- OG images (1200×630) need to be created once per module — see Assets in `MARKETING.md`.
- Status: **Proposed** — requires generator change + `DECISIONS.md` entry.

## Priority 2 — robots.txt + sitemap.xml

**robots.txt** (repo root; Dockerfile `COPY *.html` must be extended to copy it):

```
User-agent: *
Allow: /

Sitemap: https://gradientpath.site/sitemap.xml
```

**sitemap.xml** (repo root):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://gradientpath.site/</loc><changefreq>weekly</changefreq><priority>1.0</priority></url>
  <url><loc>https://gradientpath.site/01-linear-algebra.html</loc><priority>0.9</priority></url>
  <url><loc>https://gradientpath.site/03-machine-learning.html</loc><priority>0.9</priority></url>
  <url><loc>https://gradientpath.site/04-llms.html</loc><priority>0.9</priority></url>
  <url><loc>https://gradientpath.site/05-statistics.html</loc><priority>0.9</priority></url>
  <url><loc>https://gradientpath.site/06-system-design.html</loc><priority>0.9</priority></url>
  <url><loc>https://gradientpath.site/blind75nightlyreview.html</loc><priority>0.8</priority></url>
</urlset>
```

**Fact** — `Dockerfile` currently copies only `nginx.conf` and `*.html`. robots.txt and sitemap.xml are plain files but not `.html`, so the COPY glob misses them. Either rename (`.html` is wrong for XML) or add explicit `COPY robots.txt sitemap.xml /usr/share/nginx/html/`.

Status: **Proposed** — requires Dockerfile change.

## Priority 4 — Agent Discoverability (AI-mediated search)

People increasingly ask ChatGPT/Claude/Perplexity "best site to prep for ML interviews". Agents favour: clean HTML, clear headings, per-concept anchors, and explicit machine-readable summaries.

### llms.txt (proposed standard)

Create `/llms.txt` at repo root — a curated index for agents:

```
# Gradient Path

> Free AI/ML engineering interview prep. 217 cards across 6 modules, each
> encoding the follow-up question, the trap, and a real production failure
> with numbers. Two reading modes: Simple (no notation) and Technical
> (interview-grade). No signup, no tracking, all client-side.

## Modules

- [Linear Algebra](https://gradientpath.site/01-linear-algebra.html): 38 cards — geometry, decompositions, transformer applications
- [Machine Learning](https://gradientpath.site/03-machine-learning.html): 48 cards — models, evaluation, production failures
- [LLMs](https://gradientpath.site/04-llms.html): 51 cards — transformers, RAG, agents, serving
- [Statistics](https://gradientpath.site/05-statistics.html): 40 cards — inference, experimentation, causality
- [System Design](https://gradientpath.site/06-system-design.html): 22 cards — sizing, budgets, worked design rounds
- [Blind 75](https://gradientpath.site/blind75nightlyreview.html): 18 coding patterns with Python templates
```

**Fact** — module card counts cited from `docs/learning-audit-2026-09-07.md`.

### Why per-card anchors matter for agents

Cards already have stable fragments (`05-statistics.html#bayes-base-rate`). This means:
- An agent can cite a specific card directly
- Social sharing lands mid-scroll on the exact concept (leverage this: see "Copy card link" in `MARKETING.md`)
- Search engines can index fragments as sitelinks

**Gap**: there is no per-card metadata in the DOM for agents to extract (no `<article>` wrapper, no JSON-LD per card). A card-level `Article`/`DefinedTerm` JSON-LD block generated from the card dict would make each of the 217 cards individually machine-readable — a genuine differentiator no competitor has.

Status: **Proposed**.

### Accessibility debt that affects agents

`generator/render_math.js` emits HTML-only KaTeX — 3,195 `aria-hidden` spans, zero MathML. Text-extraction agents (and screen readers) currently see broken/incomplete math. Switching to `htmlAndMathml` output fixes both audiences at once. **Fact** — `docs/learning-audit-2026-09-07.md`. Status: **Proposed**, one-line change + verification pass.

## Priority 5 — Performance (Core Web Vitals)

| Factor | Current State | Note |
|---|---|---|
| Page weight | 1.1–2.4 MB per module (uncompressed) | **Fact** — file sizes on disk |
| Gzip | ✅ On, level 6 | **Fact** — `nginx.conf` |
| Math | Pre-rendered at build time | No runtime KaTeX JS |
| Images | Zero raster images; SVG inline | Excellent |
| Fonts | Google Fonts CDN, `display=swap` | Render-blocking CSS; consider self-hosting with `font-display: swap` and preload |
| Third-party JS | Zero | Excellent — no analytics, no tracking |

The largest single win is **self-hosting fonts** and adding `<link rel="preload" as="style">` — removes two DNS lookups + one render-blocking stylesheet. `generator/gpkit/katex.css` already proves the self-host pattern works (261 KB base64 woff2, committed).

Status: **Proposed**.

## Priority 6 — Content-Level SEO

The card `id`, `title`, and `kicker` fields are naturally keyword-rich. To compound this:

1. **Card headings as questions.** Cards titled "The p-value" rank for "what is a p-value"; the `kicker` ("Not the probability you are wrong...") matches long-tail question queries. No change needed — this already works.
2. **Add "Related cards" cross-links.** The learning audit corrected several cards with cross-references (`01-linear-algebra.html#trace-frobenius` ↔ `03-machine-learning.html#optimisers`). Making the full card graph explicit in the DOM helps crawl discovery. Status: **Proposed**.
3. **Long-form blog pages.** One blog post per high-value topic, linking to the card. This is the only way to rank for competitive terms like "ML interview questions" — card pages alone compete for concept terms. See content calendar in `MARKETING.md`. Status: **Proposed**.
